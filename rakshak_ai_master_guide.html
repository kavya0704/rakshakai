04 How Computer Vision & YOLO Works in Rakshak AI

YOLOv8 Target Detection Pipeline

On optical thermal cameras (Mast CAM-01) and drone gimbals (Netra-1 UAV), incoming video frames are processed by an optimized YOLOv8 nano/small edge neural model:

  1. Frame Ingestion: Captured in Infrared (IR) spectrum (8–14 μm wavelength).
  2. Bounding Box Generation: YOLO calculates coordinates (x_min, y_min, x_max, y_max) around the moving target.
  3. Confidence Score: Assigned between 0.00 and 1.00. Only detections with Confidence ≥ 0.70 are forwarded to avoid noise.
  4. Telemetry Extraction: Combines camera angle, focal length, and GPS to compute:
    • Altitude: 180 meters
    • Speed: 42.5 KM/H
    • Heading: 042° North-East (Crossing Ridge Pass)

Why Thermal IR & False-Color Spectrum?

In Himalayan high-altitude environments (Ladakh, Sikkim), daylight cameras fail in heavy snow, blizzards, and night fog.

Infrared Thermal Optic Advantage:
• Measures temperature contrast between sub-zero cold mountain background (-25°C) and warm vehicle engines / drone battery motors (+45°C).
• Pierces through whiteout snowstorms and zero-light conditions without emitting visible light that reveals forward post locations.

06 Mathematical Formulation of Core Algorithms

1. Spatio-Temporal Event Correlation Algorithm

Problem: Sensors alert independently, causing alarm fatigue. We must cluster alerts that share temporal and spatial proximity. 

ALGORITHM: SpatioTemporalCorrelation(E_new, EventDatabase)
INPUT: New event E_new = { id, sector, lat, lon, timestamp, source, confidence }
OUTPUT: Action status (EVENT_STORED | INCIDENT_CREATED | INCIDENT_UPDATED)

1. Set Time_Window_Threshold ΔT = 600 seconds (10 minutes)
2. Query Candidate_Events from EventDatabase where:
   - Event.sector == E_new.sector
   - Event.timestamp >= (E_new.timestamp - ΔT)
3. Extract Unique_Sources = { e.source for e in Candidate_Events } + { E_new.source }
4. IF Length(Unique_Sources) >= 2 (e.g. SENSOR + CAMERA):
     - Compute ExplainableRiskScore(Candidate_Events)
     - Compute TerrainAwarePatrolETA(E_new.lat, E_new.lon, E_new.sector)
     - Synthesize GroqLPU_SituationBrief()
     - Broadcast "INCIDENT_CREATED" or "INCIDENT_UPDATED" via WebSocket
5. ELSE:
     - Store as uncorroborated single-source observation.

2. Explainable 0–100 Risk Scoring Mathematical Model

Formula: The total risk score is a deterministic, additive point model bounded between 5 and 100: 

RiskScore = Min( 100, Max( 5, P_sources + P_sector + P_persistence + P_timing + P_confidence + P_weather ) )

Where:
• P_sources     : +25 pts if unique sources >= 3; +15 pts if sources == 2; +5 pts if source == 1
• P_sector      : +20 pts if sensitive border corridor (Sector B12/B14); +10 pts if buffer
• P_persistence : +17 pts if >= 3 alerts in 10 min; +10 pts if 2 alerts
• P_timing      : +10 pts if night off-hours (20:00 - 05:00 IST); +4 pts if daytime
• P_confidence  : +10 pts if average confidence >= 0.85; +6 pts if >= 0.70
• P_weather     : +8 pts if sub-zero blizzard / low-visibility distortion

SEVERITY TIERS:
• 81 – 100 : CRITICAL / HIGH PRIORITY (Immediate Human Action Required)
• 61 – 80  : HIGH
• 31 – 60  : MEDIUM
• 0  – 30  : LOW / BASELINE

3. Terrain-Aware Patrol Routing Algorithm (Haversine × Terrain Multiplier)

1. Compute Great-Circle Haversine Distance (d in kilometers):
   Δlat = lat2 - lat1
   Δlon = lon2 - lon1
   a = sin²(Δlat/2) + cos(lat1) * cos(lat2) * sin²(Δlon/2)
   d = 2 * R * atan2( √a, √(1-a) )    [where R = 6371.0 km]

2. High-Altitude Terrain Multiplier (M_terrain):
   • Snowbound Ridge (Sector B12, B14) : M = 2.2
   • Steep Rocky Pass (Sector A04, D02) : M = 1.8
   • Valley Patrol Corridor (Sector C08): M = 1.4
   • Standard Terrain                   : M = 1.0

3. Estimated Travel Time (ETA in minutes):
   ETA = ( d / Average_Vehicle_Speed_KMH ) * M_terrain * 60

   For Unit T03 (Charlie-3):
   d = 3.2 km, Speed = 35 km/h, Sector B12 (M = 2.2)
   ETA = (3.2 / 35) * 2.2 * 60 = 12.06 * 0.66 ≈ 8.0 Minutes (BEST RECOMMENDATION!)

08 Master 15 SIH Judge Counter-Question Defense Cheat Sheet

Q1 "Why doesn't Rakshak AI shoot down or intercept drones automatically?"
Winning Answer: "Respected Judges, Rakshak AI is deliberately designed as an operational intelligence layer, not a weapon. In high-altitude border security (ITBP context), shooting down every detected blip causes friendly fire, civilian casualties, and legal violations. Our principle is: 'Person detected does NOT equal threat detected'. Rakshak AI correlates multiple feeds, calculates explainable risk, and empowers the human commanding officer to make the final informed tactical decision."
Q2 "How do you prevent false alarms from mountain wildlife (Yaks, Snow Leopards)?"
Winning Answer: "Single-sensor systems suffer from massive false alarms. A yak walking on a ridge might trigger a ground seismic sensor, but it will NOT simultaneously trigger a thermal optical vector with UAV velocity, nor will it correlate with a drone observer. Rakshak AI requires multi-source spatio-temporal cross-corroboration (≥2 independent source types within a 10-minute window) before escalating an incident."
Q3 "What if there is no internet in remote high-altitude Himalayas (Ladakh / Sikkim)?"
Winning Answer: "Rakshak AI has an Edge-First Architecture. The core correlation engine, risk mathematical model, and SQLite database run 100% offline on local forward tactical servers (Tactical C2 nodes). When cloud connectivity is available, Groq LPU enhances natural language sitreps; if the link drops, our deterministic rule engine ensures 100% operational continuity with zero downtime."
Q4 "Is your Risk Score a Black Box AI prediction?"
Winning Answer: "No, sir. We explicitly avoid black-box probabilistic hallucinations. Our risk score is 100% deterministic and explainable: +25 pts for multi-source consensus, +20 pts for sensitive sector proximity, +17 pts for time clustering, +10 pts for night timing, and +10 pts for optic confidence. The officer can inspect the exact mathematical points breakdown on screen."
Q5 "How does the Patrol Routing Algorithm work?"
Winning Answer: "Standard GPS navigation uses straight-line distance, which is lethal in the Himalayas where climbing a 2 km ridge can take 4 hours. Rakshak AI uses Haversine Great-Circle distance weighted by high-altitude terrain multipliers (2.2x for snowbound ridges, 1.8x for rocky passes). This gives the duty officer an accurate estimated travel time (ETA in minutes) so the optimal response unit is dispatched."
Q6 "Why did you use Groq LPU instead of standard OpenAI or HuggingFace?"
Winning Answer: "In military command and control, latency is critical. Standard cloud GPUs take 3 to 8 seconds to generate a response. Groq's Language Processing Unit (LPU) uses deterministic Tensor Streaming architecture that delivers complete operational sitreps in under 0.4 seconds (over 500 tokens/sec), ensuring zero lag in life-critical tactical environments."
Q7 "How does the Manual Drone Operator Input support Human-AI collaboration?"
Winning Answer: "On the '/sources' page, human forward observers can manually enter visual sightings. Rakshak AI ingests human intelligence as a first-class data feed and correlates it against automated seismic and thermal camera alerts, achieving genuine Human + AI intelligence fusion."
Q8 "What happens if an equipment asset like Tatra V12 overheats?"
Winning Answer: "Our predictive telemetry engine monitors engine temperature (>85°C warning, 94.5°C alert) and chassis vibration (>3.5 mm/s warning). When an alert is detected, the system flags the vehicle on the Equipment Health dashboard and prevents the patrol engine from recommending a degraded vehicle for an emergency high-altitude sortie."
Q9 "How do you ensure audit accountability if an officer makes a mistake?"
Winning Answer: "Every single action — from raw sensor ingestion to AI recommendations and human officer approvals — is cryptographically timestamped and recorded in the read-only System Audit Log (`/audit`) and compiled into formal After-Action Reports (`/reports`)."
Q10 "What is the computational complexity of the Spatio-Temporal Correlation Core?"
Winning Answer: "By using an indexed sliding temporal window of ΔT ≤ 600s and spatial sector partitioning (Spatial Hashing / Geofence Bucketing), candidate evaluation operates in O(k) time where k is the number of active alerts in that sector (typically k < 20), achieving sub-millisecond execution even with thousands of sensors."
