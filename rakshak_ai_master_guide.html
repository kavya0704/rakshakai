4. Core Algorithms & Mathematical Formulations

ALGORITHM 1: Spatio-Temporal Event Correlation Engine

Goal: Group disconnected sensor alerts into a single unified incident if they happen in the same place around the same time.

Mathematical Rule:

Given an event E_new = (Location L, Timestamp T, Source S):
1. Candidate Pool: Find all recent events E_i where |T_new - T_i| ≤ 600 seconds (10 mins).
2. Spatial Match: Haversine_Distance(L_new, L_i) ≤ 120 meters OR Sector(E_new) == Sector(E_i).
3. Cross-Corroboration Check: Count unique sources {S_1, S_2, ... S_k}.
   If k ≥ 2 (e.g. SENSOR + CAMERA), PROMOTE TO CORRELATED INCIDENT!

ALGORITHM 3: Terrain-Aware Patrol Routing (ETA Engine)

Goal: Recommend the nearest ready patrol unit accounting for steep Himalayan snow terrain. 

1. Haversine Great-Circle Distance:
   d = 2 * R * arcsin( sqrt( sin²(Δlat/2) + cos(lat1)*cos(lat2)*sin²(Δlon/2) ) )
   where R = 6371 km (Earth's radius).

2. Terrain Difficulty Multipliers (High-Altitude Context):
   • Snowbound Mountain Ridge (Sector B12, B14) : 2.2x
   • Steep Rocky Pass (Sector A04, D02)          : 1.8x
   • Foothills / Valley Corridor (Sector C08)   : 1.4x
   • Standard Patrol Trail                      : 1.0x

3. Estimated Travel Time (ETA in Minutes):
   ETA = ( Distance_km / Average_Speed_kmh ) * Terrain_Multiplier * 60
   For Unit T03: (3.2 km / 35 km/h) * 2.2 * 60 ≈ 8.0 Minutes (RECOMMENDED!)

7. SIH Judge Counter-Question Defense Cheat Sheet 🛡️

Q1: "Why doesn't Rakshak AI shoot down or intercept the drones automatically?"

Winning Answer: "Respected Judges, Rakshak AI is deliberately designed as a non-kinetic operational intelligence layer, not a weapon. In high-altitude border security (ITBP context), shooting down every detected blip causes friendly fire, civilian casualties, and legal violations. Our principle is: 'Person detected does NOT equal threat detected'. Rakshak AI correlates multiple feeds, calculates explainable risk, and empowers the human commanding officer to make the final informed tactical decision."

Q2: "How do you prevent false alarms from mountain wildlife (e.g. Snow Leopards, Yaks)?"

Winning Answer: "Single-sensor systems suffer from massive false alarms. A yak walking on a ridge might trigger a ground seismic sensor. However, a yak will NOT simultaneously trigger a thermal optical vector with UAV characteristics, nor will it correlate with a low-altitude aerial drone observer. Rakshak AI requires multi-source spatio-temporal cross-corroboration (≥2 independent source types within a 10-minute window) before escalating to a high-priority incident."

Q3: "What if there is no internet in remote high-altitude Himalayas (Ladakh/Sikkim)?"

Winning Answer: "Rakshak AI has an Edge-First Architecture. The core correlation engine, risk mathematical model, and SQLite database run completely offline on local forward tactical servers (Tactical C2 nodes). When cloud connectivity is available, Groq LPU enhances the natural language sitreps; but if the link drops, our deterministic rule engine ensures 100% operational continuity with zero downtime."

Q4: "Is your Risk Score a Black Box AI prediction?"

Winning Answer: "No, sir. We explicitly avoid black-box probabilistic hallucinations. Our risk score is 100% deterministic and explainable: +25 pts for multi-source consensus, +20 pts for sensitive sector proximity, +17 pts for time clustering, +10 pts for night timing, and +10 pts for optic confidence. The officer can click any score and see the exact mathematical points breakdown."

Q5: "How does the Patrol Routing Algorithm work?"

Winning Answer: "Standard GPS navigation uses straight-line distance, which is lethal in the Himalayas where a 2 km ridge might take 4 hours to climb. Rakshak AI uses Haversine Great-Circle distance weighted by high-altitude terrain multipliers (2.2x for snowbound ridges, 1.8x for rocky passes). This gives the duty officer an accurate estimated travel time (ETA in minutes) so the optimal response unit is dispatched."
